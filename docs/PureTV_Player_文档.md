# 上篇：产品需求文档 PRD
## 1 文档概述
### 1.1 文档目的
通过深度分析市面主流TVBox播放器优缺点，吸收竞品全部优点，规避行业常见缺陷，输出完整产品需求，用于开发立项、功能排期、产品迭代。
### 1.2 竞品选型
TiviMate、IPTV Smarters Pro、Perfect Player IPTV、Kodi、Stremio
### 1.3 产品定位
全能免费TVBox影音播放器，大屏原生极致体验，直播点播双全能，低配设备流畅运行；小白零门槛，同时支持专业拓展；纯净无广告，Android TV/盒子/安卓手机全平台兼容。

## 2 竞品分析
### 2.1 TiviMate
✅优点：TV原生交互优秀；EPG节目单体验好；播放稳定，4K硬解可靠；频道分组收藏完善；支持手机遥控。
❌缺点：高级功能收费；仅Android TV；无点播/海报墙；协议支持有限；设备绑定。

### 2.2 IPTV Smarters Pro
✅优点：全平台；新手引导友好；基础直播点播EPG免费；支持多源。
❌缺点：UI为手机移植，TV焦点错乱；大M3U解析卡顿；4K硬解不稳定；无影视刮削美化；EPG排版差。

### 2.3 Perfect Player IPTV
✅优点：低配盒子兼容性极强；自定义皮肤；内存占用极低；稳定。
❌缺点：功能单薄；EPG简陋；无海报墙、剧集管理；无插件拓展。

### 2.4 Kodi
✅优点：开源免费；插件生态强大；本地影音刮削海报、字幕能力强；格式支持全面。
❌缺点：上手难度高；原生TV交互差；第三方插件不稳定；低配盒子容易卡顿；直播换台慢。

### 2.5 Stremio
✅优点：现代化海报墙UI；资源聚合、剧集追更；安装包轻量。
❌缺点：直播IPTV能力弱；免费源卡顿；播放设置简陋；缺少EPG回看预约。

## 3 竞品优缺点汇总
### 3.1 需要吸收的优点
1. 兼容老旧低配盒子，低功耗低内存占用
2. 原生TV遥控器交互，焦点流畅，大屏专属UI
3. 直播IPTV + 影视点播 + 本地播放一体化
4. 支持M3U/Xtream等主流协议，大容量频道列表快速解析
5. 插件拓展、TMDB海报刮削、字幕自动匹配
6. 4K/HEVC硬解，长时间播放稳定
7. 新手引导，极简/专业双模式
8. 跨设备同步收藏、播放记录、配置

### 3.2 需要规避的缺陷
1. 不做设备绑定、不限设备数量
2. UI原生TV设计，杜绝手机移植界面、焦点错乱
3. 大频道列表解析不卡死，带加载进度提示
4. 功能不偏科，直播点播兼顾
5. 降低上手门槛，高级功能隐藏
6. 自研播放内核，避免第三方插件不稳定
7. 核心功能永久免费，无强制广告
8. 智能缓冲，弱网自动切换源；完善EPG时间轴、回看预约

## 4 产品核心设计原则
1. 体验优先：原生TV大屏交互，遥控器低学习成本
2. 性能极致：秒启动、秒解析，老旧盒子流畅运行
3. 功能全能：直播、点播、本地影音、EPG、海报墙
4. 双模式：小白极简模式 + 专业高阶模式一键切换
5. 纯净免费：核心影音功能永久免费，无开屏弹窗广告
6. 高拓展：插件系统、源备份导入导出

## 5 详细功能需求
### 5.1 设备与系统适配需求
1. 支持Android TV、电视盒子、智能电视、安卓手机全设备安装运行。
2. 兼容低端老旧设备（1G运存、低端芯片），后台常驻不卡顿、不杀进程。
3. 无需设备MAC绑定、无设备数量限制，多设备随意登录同步配置。
4. 启动速度≤1秒，后台重启无加载延迟，长期运行无内存泄漏。

### 5.2 UI与交互需求
1. 全界面原生TV大屏适配，大图标、宽排版、焦点高亮、移动丝滑。
2. 遥控器完美适配：上下换台、左右切换分类、OK确认、返回退出、菜单呼出逻辑统一。
3. 支持自定义皮肤、字体大小、焦点样式、界面布局。
4. 首页模块化：直播专区、影视点播、本地影音、我的收藏、播放记录、设置中心。
5. 海报墙沉浸式展示：电影/剧集高清海报、评分、年份、简介、演员信息。

### 5.3 直播IPTV功能需求
1. 支持M3U、Xtream Codes主流协议，兼容市面所有主流直播源。
2. 大容量频道列表秒解析，解析过程显示进度条，界面不卡死、可操作。
3. 频道分组、自定义分类、收藏置顶、清晰度记忆、换台提速。
4. EPG系统：实时节目单、时间轴预览、四流马赛克画面、节目预告、回看、预约播放。
5. 直播低延迟、智能缓冲、网络波动自动纠错，减少断流卡顿。

### 5.4 影视点播功能需求
1. 电影、电视剧、综艺、动漫全品类聚合分类。
2. 自动刮削TMDB信息，匹配海报、简介、评分、演员表、分集信息。
3. 智能追更：剧集自动更新、未看完集数标记、断点续播。
4. 支持清晰度智能切换（自动根据网速切换1080P/4K）。
5. 支持Real-Debrid、TorBox高级拓展，加载高清稳定资源。

### 5.5 播放内核性能需求
1. 稳定播放内核，兼容MP4、MKV、TS、FLV等所有视频编码格式。
2. 4K、HEVC、H265硬件加速解码，高码率流畅播放、无花屏、无掉帧。
3. 智能缓冲策略：弱网预加载、强网提速、卡顿自动切换备用源。
4. 支持倍速播放、字幕加载、音轨切换、画面比例调节。
5. 本地播放+网络播放双优化，兼顾本地影音库与在线流媒体。

### 5.6 易用性设计
1. 新手引导式配置，一键导入源、一键初始化，零基础可用。
2. 默认极简模式：隐藏复杂设置，只展示核心播放、收藏、记录功能。
3. 支持切换专业模式：开放插件、解码参数、缓冲参数、界面自定义全部权限。
4. 内置使用教程、常见问题修复、源检测工具。

### 5.7 拓展与生态需求
1. 支持轻量化插件市场，可按需安装字幕插件、资源插件、美化插件。
2. 插件官方审核上架，杜绝闪退、崩溃、恶意插件，稳定性可控。
3. 支持配置、收藏、播放记录云端同步，多设备互通。
4. 支持自定义源导入、导出、备份、一键恢复。

### 5.8 商业化与纯净度需求
1. 核心影音功能100%永久免费：直播、点播、EPG、海报墙、解码全部免费。
2. 无开屏广告、无弹窗广告、无插播广告、无后台推送广告。
3. 增值付费仅针对：高级自定义皮肤、专属云端空间、无水印美化，不影响基础使用。

## 6 非功能需求
1. **稳定性**：连续播放24小时无闪退、无断流、无崩溃，后台常驻稳定。
2. **兼容性**：覆盖99%电视盒子、智能电视、安卓设备，新旧机型全适配。
3. **流畅度**：页面切换0延迟、换台0卡顿、列表滑动丝滑。
4. **安全性**：无隐私窃取、无后台偷跑流量、无恶意权限请求。
5. **轻量化**：安装包体积小、占用内存低、待机功耗极低。

## 7 产品最终差异化优势
1. 比TiviMate免费、跨平台、功能更多（点播+聚合资源）。
2. 比Smarters Pro UI更专业、TV适配更好、解析更快、画质更稳。
3. 比Perfect Player功能全面、现代化观影体验、生态更强。
4. 比Kodi简单易用、稳定不崩、无需复杂配置。
5. 比Stremio专业直播能力、完善EPG、设备适配更强。

## 二、开发语言 & 技术框架
### 2.1 开发语言
- **Kotlin**：主开发语言，业务逻辑、页面、播放器、源解析、EPG模块开发
- **Java**：少量遗留兼容代码（推荐新项目尽量纯Kotlin）
- **C/C++**：用于FFmpeg硬解/软解底层播放模块（JNI调用）
- **XML**：Android 原生布局资源、color.xml主题色定义、style样式
- **Markdown**：项目文档、接口文档、开源README

> 说明：Android TV应用，不使用Flutter/React Native等跨平台方案，原生开发保证遥控器焦点、低配置盒子性能稳定。跨平台框架在TV遥控器焦点、内存占用、硬解兼容性上缺陷较多，不符合本项目低配盒子流畅要求。

### 2.2 核心技术框架 & 依赖库
#### UI层框架
1. **Jetpack Compose TV**（推荐）：构建TV端界面，原生支持主题切换、动态换肤，可实现跟随系统/浅色/深色三套主题一键切换；
    > 备选方案：Android View体系 + Theme/Style，color.xml分三套主题资源，适合更老旧设备兼容
2. **Jetpack AppCompat**：夜间模式、系统主题监听，实现「跟随系统」自动切换深浅色
3. **Jetpack Lifecycle**：页面生命周期管理，防止内存泄漏
4. **Jetpack ViewModel**：页面数据保存，主题切换不丢失列表、播放状态
5. **Jetpack Navigation**：页面路由管理
6. **Material3 TV**：Material 3大屏组件库，适配TV遥控器焦点、按钮、卡片组件

#### 播放器内核
1. **ExoPlayer**：基础播放器，扩展支持M3U、HLS流媒体；
2. **FFmpeg（JNI）**：扩展编码支持，软解兜底，处理ExoPlayer无法兼容的流媒体格式；

#### 数据 & 网络模块
1. **OkHttp + Retrofit**：网络请求，源拉取、EPG节目单下载、TMDB影视信息刮削
2. **Kotlin Coroutines + Flow**：异步任务，频道列表解析、后台更新，解析时UI不卡死
3. **Room Database**：本地数据库，存储频道列表、播放记录、收藏、EPG缓存
4. **DataStore**：轻量持久化，保存主题选择、用户设置、配置项（替代SharedPreferences）

#### 其他关键依赖
1. **Coil**：图片加载，海报墙图片加载、缓存，适配Kotlin Compose
2. **TMDB SDK**：影视元数据、海报、简介、演员信息刮取
3. **Moshi**：JSON序列化，解析xtream、epg、源配置文件
4. **Dagger Hilt**：依赖注入，统一管理全局实例（播放器、网络、数据库）

### 2.3 构建环境
- 构建工具：Gradle Kotlin DSL
- IDE：Android Studio（Android TV开发）
- 最低SDK版本：API 21（Android 5.0，兼容老旧电视盒子）
- 目标SDK版本：API 34

## 六、跟随系统主题模式（智能适配模式）
### 技术逻辑（开发核心逻辑）
1. 读取Android TV系统夜间模式状态
2. 系统开启深色模式 → 自动加载【深色主题全套色值】
3. 系统关闭深色模式 → 自动加载【浅色主题全套色值】
4. 系统主题切换时，APP 无闪屏实时动态换肤，无需重启应用
5. 跟随系统为软件默认出厂主题

> 所有颜色复用上述两套主题，无需新增色值，减少打包体积与冗余代码

## 七、全局UI通用技术规范（TV大屏专属强制要求）
### 7.1 文字统一规范
1. 所有文字禁止加粗过度，一级文字常规加粗，二三级文字常规字重
2. TV端最小文字尺寸不小于14sp，远距离可视
3. 所有文字禁止锯齿、模糊，开启系统抗锯齿渲染

### 7.2 焦点通用规范（解决市面TVBox焦点乱跑、看不清通病）
1. 所有可点击控件统一焦点边框、统一动效
2. 焦点移动带有匀速缓动动画，无闪烁、无瞬移
3. 卡片焦点支持轻微缩放（1.02倍）+ 边框高亮双重提示

### 7.3 配色禁忌（开发强制规避）
1. 禁止低对比度文字，保证TV 3米外清晰可读
2. 禁止杂色、多色混用，全局仅蓝白灰黑体系，极简高级
3. 禁止主题切换残留色值、UI错乱、缓存不刷新

## 八、主题切换实现简要说明
> 若使用Jetpack Compose：通过`MaterialTheme`动态替换colorScheme，监听DataStore保存的主题选项，同时监听系统夜间模式变化，自动重组界面，实现动态换肤。
>
> 若使用传统XML View：定义三套`styles.xml`，`colors.xml`拆分成`colors_dark.xml`、`colors_light.xml`，通过AppCompatDelegate设置夜间模式。
